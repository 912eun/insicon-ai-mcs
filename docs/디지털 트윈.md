# 디지털 트윈?

## Digital Twin이란?

한 줄 정의:

> **"실제 시스템의 가상 복제본으로, 실시간으로 연동되어 시뮬레이션·모니터링·최적화에 활용되는 것"**
> 

---

## 근데 그냥 시뮬레이션이랑 뭐가 달라?

아까 읽은 Shao et al. (2019) 논문이 이걸 정확히 짚었어요.

```
[Digital Model]
가상 모델만 존재
실제 시스템과 연결 없음
← 일반 시뮬레이션

[Digital Shadow]
실제 → 가상 단방향 연결
센서 데이터를 모델에 반영

[Digital Twin]
실제 ↔ 가상 양방향 연결
모델이 실제에 영향을 줌
← 진짜 Digital Twin
```

핵심은 **양방향 실시간 연동**이에요.

---

## 우리 프로젝트에서 Digital Twin은 뭐냐

```
실제 Fab (Physical)
AMR 위치, 공정 상태, 반송 요청
        ↕ 실시간 동기화
Digital Twin (Virtual)
Minifab/SMT2020 시뮬레이터
        ↕
AI MCS (RL 에이전트)
"어떤 AMR 보낼지" 결정
        ↓
다시 실제 Fab에 명령 전달
```

---

## 솔직히 말하면

우리 프로젝트에서 Digital Twin은 사실 **"RL 학습 환경 + 실시간 상태 반영 시뮬레이터"** 예요.

거창하게 들리지만 실제로 하는 일은:

**① 오프라인 학습 환경** — RL 에이전트가 실제 Fab 건드리지 않고 시뮬레이터에서 학습

**② 실시간 상태 반영** — 실제 AMR 위치·공정 상태를 시뮬레이터에 동기화

**③ 의사결정 지원** — 학습된 에이전트가 실시간으로 배정 결정

이 세 가지예요. 복잡한 3D 시각화나 물리 엔진 같은 건 우리 스코프 밖이에요.

---

## 왜 Digital Twin이라고 부르는 게 중요한가

사실 "시뮬레이터"라고 불러도 되는데, Digital Twin이라고 부르는 이유가 있어요.

```
시뮬레이터:
"만약 이렇게 하면 어떻게 될까?"
(가정 기반)

Digital Twin:
"지금 실제 상황에서 어떻게 해야 하나?"
(실시간 기반)
```

우리가 만드는 건 실제 Fab 상태를 받아서 실시간으로 결정하는 거니까 Digital Twin이 맞아요.
