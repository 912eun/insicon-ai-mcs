# 반도체 Fab 구조

```smalltalk
┌─────────────────────────────┐
│   MES (Manufacturing        │  ← "무엇을 언제 만들까?"
│   Execution System)         │     생산 계획·공정 지시
└──────────────┬──────────────┘
│
┌──────────────▼──────────────┐
│   MCS (Material Control     │  ← "웨이퍼를 어디로 보낼까?" ★
│   System)                   │     이송 요청 발생·AMR 배정 (의사결정)
└──────────────┬──────────────┘
│
┌──────────────▼──────────────┐
│   ACS (Automated Control    │  ← "어떤 경로로 갈까?"
│   System)                   │     실제 AMR 경로 계산·이동 (CBS 알고리즘)
└─────────────────────────────┘
```

### MCS가 하는 일 구체적으로

| 역할 | 내용 |
| --- | --- |
| **반송 요청 수신** | MES로부터 "A공정 끝난 웨이퍼를 B공정으로 보내라" 명령 수신 |
| **AMR 선택** | 현재 가용한 AMR 중 가장 적합한 것 선택 (← **우리가 RL로 하는 것**) |
| **우선순위 결정** | Hot Lot(긴급)을 먼저? 대기시간 긴 것 먼저? |
| **ACS에 명령** | 선택된 AMR에게 "픽업 위치 → 드롭오프 위치로 이동" 지시 |
| **상태 모니터링** | 각 AMR의 위치·상태·배터리 실시간 추적 |

---

### 우리 프로젝트에서 MCS의 위치

우리 제안서의 "AI MCS"가 정확히 이 역할이에요.

```smalltalk
Digital Twin (상태 제공)
        ↓
AI MCS ← 우리가 만드는 것
  ├── 혼잡 예측 모델 (LSTM)
  ├── RL 디스패처    ← "어떤 AMR에 배정?"
  └── LLM 운영자 지원
        ↓
ACS (CBS 알고리즘으로 실제 경로 계산)
        ↓
AMR 이동
```

즉 **MCS = RL 디스패처가 들어가는 바로 그 자리**예요. 우리가 RL로 교체하려는 게 기존의 규칙 기반 MCS(FIFO, EDD 등)인 거고요.
