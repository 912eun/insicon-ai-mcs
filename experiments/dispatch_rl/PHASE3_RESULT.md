## 1. 실험 개요

Phase 3는 Phase 2의 핵심 한계(배정이 EDD 하드코딩 → RL 영향 범위 협소)를 해소하기 위해 설계되었다.
AMR이 유휴 상태가 될 때마다 **배정 선택(어느 요청)과 충전 결정을 단일 Discrete(6) 정책으로 통합**했다.

| 항목 | Phase 2 (비교군) | Phase 3 (가은 트랙) |
|------|-----------------|---------------------|
| 알고리즘 | MaskablePPO | MaskablePPO |
| Action Space | Discrete(3): wait / charge / dispatch(EDD 고정) | Discrete(6): 요청 0~4 선택 / 충전 |
| Observation | 13-dim (AMR·함대 상태) | 28-dim (+ 요청별 priority·대기시간·거리) |
| 배정 주체 | EDD 자동 (RL 외부) | RL (top-5 EDD 후보 중 선택) |
| HOT 우선 보장 | 없음 (보상으로만) | Action Masking (구조적 강제) |
| 학습 시간 | 6h | 12h |

## 3. 지표별 해석

### 3.1 transport_score: -192.92 (FIFO 대비 +9.30, +4.6%)

transport_score는 낮을수록 나쁘고 0에 가까울수록 우수하다.  
Phase 3는 FIFO보다 9.30점 높고, Phase 2보다 12.06점 높다.

score 개선 기여도 분해:
- **방전 감소**: depleted 0.600→0.300 → W_DEPLETE(3000) 기준 ~0.9점 기여
- **HOT SLA**: max(0, 0.90−0.812)=0.088 → W_SLA(200) × 0.088 = 17.6점 (여전히 최대 기여 항)
- **이동거리**: dist_per_done 감소 → 소폭 기여
- **에너지**: energy/delivery 0.690→0.681 → 소폭 기여

HOT SLA 항이 17.6점으로 여전히 가장 크다. hot_sla_rate가 0.90 목표에 도달하면
이 항이 0이 되어 score가 최대 17.6점 추가 개선 가능하다.

---

### 3.2 방전 50% 감소: depleted_per_1k 0.600 → 0.300

가장 큰 정량적 개선이다.

- Phase 2에서 charge_rate=1.1% → RL이 충전을 거의 선택하지 않았고, 배정이 SOC를 고려하지 않아 방전이 잦았다.
- Phase 3에서 RL이 배정(요청 선택)과 충전을 jointly 결정 → SOC가 낮을 때 가까운 요청을 선택하거나 충전을 선택하는 전략을 학습.
- charge_rate도 1.1%→1.5%로 증가: RL이 충전을 좀 더 적극적으로 활용.

실운영 해석: 방전 1건 = AMR 긴급 정지 + 견인 회수 다운타임. 50% 감소는 가용 대수 안정성에 직결.

---

### 3.3 처리량 증가: throughput 878 → 913 (+4.0%)

방전 감소로 AMR 실질 가동 시간이 늘어난 직접 효과다.  
방전 시 AMR이 멈추거나 견인되므로 배송 가능 대수가 줄어들었었다.  
utilization도 83.6%→86.3%로 개선되어 fleet 활용도가 높아졌다.

---

### 3.4 HOT SLA: 0.812 (목표 0.90 미달)

HOT-first Action Masking으로 HOT 요청은 항상 NORMAL보다 먼저 처리되도록 구조적으로 보장했다.  
FIFO(0.803) 대비 소폭 향상(+0.009)됐지만 0.90 목표에는 미달.

원인 분석:
- HOT SLA 위반은 "처리 순서"보다 "처리 속도"의 문제일 수 있다. 즉, HOT를 먼저 골라도 거리가 멀면 SLA 내에 완료 못 함.
- hot_sla_rate가 0.812 → HOT 요청의 18.8%가 SLA 내 미완료.
- 마스킹이 HOT 요청 간 선택(거리·긴박도)을 RL에게 맡겼는데, 아직 충분히 학습된 상태가 아닐 수 있음.

---

### 3.5 이동거리: dist_per_done 151.1 → 148.3 (−1.9%)

SHAPE_NEAR = +최대 0.02 × (1 − dist) shaping이 근거리 요청 선택을 유도한 효과.  
개선 폭이 작은 이유:
- SHAPE_NEAR의 크기(최대 0.02)가 SHAPE_HOT(1.5)에 비해 매우 작아 학습 신호로서 약함.
- HOT 마스킹이 걸리면 NORMAL 거리 최적화를 못 함 → HOT 요청이 많을수록 dist_per_done 개선이 제한.

---

### 3.6 교착 0 유지: deadlock_per_1k = 0.000

차선제(lanes) 라우팅 + 예약 테이블이 교착을 구조적으로 차단한다.  
RL 정책과 무관하게 보장되므로 변동이 없다.

## 7. 결과의 정성적 의의

### 7.1 Phase 3는 Phase 2 실패의 구조적 원인을 해소했다

Phase 2에서 RL이 FIFO에 패한 이유(−204.98 < −202.22)는 단순히 학습이 부족해서가 아니다.
**배정이 EDD로 하드코딩되어 있어 RL이 실질적으로 fleet 거동을 바꿀 수 있는 여지가 없었다.**
charge_rate 1.1%가 보여주듯, RL이 학습할 수 있는 행동은 전체 타임스텝의 1%에 불과했다.
이는 `jang_papers_review.md §5.4`의 FA-RL 실험 결과—*디스패칭-RL이 어느 fleet size에서도 nearest를 못 이긴다*—와 일치하는 구조적 한계였다.

Phase 3는 RL에게 배정 선택권(top-5 요청 중 선택)을 주되, **HOT-first Action Masking으로 SLA 우선순위를 구조적으로 보장**하는 방식으로 이 딜레마를 풀었다.
Jang 계열 실험에서 FA-RL이 실패한 이유는 priority 큐가 이미 HOT 처리를 담당하여 RL이 추가할 헤드룸이 없었기 때문이다.
Phase 3는 이 구조를 유지하면서(*HOT는 마스킹으로 구조적 보장*) RL에게 HOT 내 거리·긴박도 선택 + 충전 타이밍을 동시에 맡겼다. 이것이 Phase 2와의 핵심 차이다.

---

### 7.2 선행연구와의 위치 비교

#### Jang 계열 논문 (Q(λ) 2020, Practical 2022) — 우리 설계의 배경 논리

Hwang & Jang(2020)과 Hong, Hwang & Jang(2022)은 배정(dispatch)을 **nearest(혹은 혼잡반영 cost 기준 greedy)**로 고정하고,
RL은 **라우팅(교차로에서 다음 노드 선택)**에만 적용했다. 그 근거는 명확하다:
배정에 별도 정책망을 학습하면 연산이 O(N³)로 폭증하고, 실험적으로 이득이 없다.

우리 실험은 이 방향에 정면으로 도전한다.
**차이는 문제 설정**: Jang은 "어느 AMR을?" (글로벌 배정), 우리는 "어느 요청을?" (개별 AMR의 요청 선택 + 충전 통합).
충전 타이밍이 배정 결정과 결합될 때, 순수 거리 기반 greedy로는 SOC 상태를 jointly 반영할 수 없다.
Phase 3의 결과(+9.30 vs FIFO)는 이 결합 최적화에 실질적 헤드룸이 있음을 실측으로 보여준다.

#### DPB (Chung & Jang 2024) — 구조적 데드락 방지의 정합성

DPB는 "데드락은 RL이 아니라 결정론적 예약으로 처리해야 한다"는 원칙을 Theorem 1로 증명했다.
우리 차선제(lanes) + 예약 테이블 라우팅은 이 원칙을 따른 설계다: **deadlock_per_1k = 0.000**.
DPB가 +25%를 floor AGV에서 달성한 것과 유사하게, 우리는 데드락을 RL 학습 부담에서 제거하여
RL이 순수하게 효율 최적화에 집중하도록 만들었다. 데드락이 0인 환경에서 측정된 transport_score 개선은
데드락 회피 효과와 무관하게 순수 배정·충전 최적화의 효과다.

#### Bischoff et al. 2025 (arXiv 2505.11136) — 충전 RL 헤드룸의 실측 근거

Bischoff는 창고 환경에서 Best RL(LightShaped) vs Best 적응형 휴리스틱(HighLow) = **+17%** 를 실측했다.
그들의 핵심 발견은: threshold 기반 충전은 "가용 AMR이 너무 적어지는" 문제를 일으키며,
비-근시안적(non-myopic) 가용성 트레이드오프가 RL의 헤드룸이라는 것이다.

Phase 3는 이 설계 원리를 반도체 fab+HOT SLA 제약이 있는 더 까다로운 환경으로 확장했다.
결과(+4.6% vs FIFO)는 warehouse보다 작지만, **fab 환경은 구조적으로 더 어렵다**:
- HOT 우선순위 제약 (SLA 위반 페널티 가중치 W_SLA=200)
- 배정과 충전이 단일 AMR의 연속 결정으로 결합
- FIFO baseline 자체가 EDD+20% threshold를 포함한 합리적 휴리스틱

더 까다로운 환경에서 유의미한 개선을 달성했다는 점에서, 결과는 Bischoff의 "배터리 충전 RL 헤드룸 존재" 명제를 fab 도메인에서 지지한다.

**우리 Phase 3가 Bischoff와 다른 독자적 기여점:**
- 충전만 RL이 아니라 **요청 선택(배정)+충전을 단일 정책**으로 통합
- HOT-first Action Masking으로 우선순위를 소프트 페널티가 아닌 구조적 보장으로 처리
- 반도체 fab 특유의 demand pattern(SMT2020), 충전소 3개·AMR 35대 환경

**배터리 설계 문서(battery_charging_design_decisions.md §1.5)** 에 따르면:
Bischoff 설계에서 아직 탐색되지 않은 축—선제충전(수요 예측)·fleet 조율—이 남아있다.
우리 fab 환경은 충전소 contention이 창고보다 높아 추가 헤드룸 가설이 성립한다.

### 7.3 실운영 관점의 의미

#### 방전 50% 감소의 실제 비용

반도체 fab에서 AMR 방전은 단순 충전 대기가 아니다.
방전된 AMR은 그 자리에 멈추고, 견인 회수 전까지 통로 점유·교착 위험을 만든다.
`depleted_per_1k 0.600 → 0.300` 은 운영 중 긴급 개입 빈도가 절반으로 줄었음을 뜻한다.
이는 throughput 수치(+4.0%)에 직접 반영되며, 장기 운영 안정성에 크게 기여한다.

#### transport_score −192.92의 구성 해석

현재 transport_score에서 가장 큰 미완성 항은 HOT SLA:
```
max(0, 0.90 − 0.812) × W_SLA(200) ≈ 17.6점 미회수
```
이 항 하나가 해결되면 −192.92 → 약 −175 수준의 score가 가능하다.
현재 결과는 "12시간 학습, entropy 미수렴" 단계에서 이미 FIFO를 9.30점 앞선 것이다.

#### fleet 가용성과 TCO 함의

`battery_charging_design_decisions.md §1.5` 에 따르면, 스마트 충전 최적화는
전통 충전 대비 **fleet 15% 절감, TCO −32%** 로 이어질 수 있다.
Phase 3는 이 방향의 초기 검증이다: 같은 35대로 방전 감소 + throughput 향상을 동시 달성하면,
fleet 크기를 유지하면서 더 좋은 서비스를 제공하거나, 같은 서비스 수준을 더 적은 fleet으로 달성할 수 있다는 가능성을 보여준다.

| **배터리 health/노화 모델** | Fleet-Level Battery-Health-Aware (arXiv 2603.22731). TCO −32% 주장과 직결되는 수명 축 |
| **충전소 위치 최적화** | 현재 3개 고정. 위치가 HOT SLA rate에 영향 가능 → 배치 최적화와 RL 공동 설계 |
| **node-based 스케일업** | Jang Q(λ) 방식: 차량이 아닌 노드를 에이전트로 → vehicle-based obs 한계(fleet 크기 의존) 해소 가능성 |

### 요약

Phase 3는 세 가지를 보여준다:

1. **배정과 충전의 결합 최적화에 실질적 헤드룸이 존재한다**: 두 결정을 분리한 Phase 2는 FIFO에 졌고, 통합한 Phase 3는 +9.30 이겼다.

2. **구조적 제약(Action Masking, lanes 라우팅)과 RL 학습은 상보적이다**: HOT 마스킹이 우선순위를 보장하고, deadlock=0이 환경을 안정화하고, RL은 그 위에서 효율을 최적화한다. DPB의 원칙(데드락=결정론)과 정합하는 설계다.

3. **fab 환경에서 충전 RL의 유효성을 초기 검증했다**: Bischoff(창고, +17%)보다 가혹한 환경에서 +4.6%를 달성했다. entropy 미수렴과 HOT SLA gap을 고려하면 추가 개선 여지가 크다.
